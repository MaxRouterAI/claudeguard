# macOS 通知诊断与验收

入口在监测条的“通知诊断”。原黑灰主布局不变，诊断在弹层中显示，不修改系统设置。

## 三种证据分开显示

1. **系统已接收**：UserNotifications 的提交回调成功，仅说明系统接受请求。
2. **通知中心记录**：只查询本应用的通知标识，按本次运行的唯一测试标识匹配；显示查询时间。找到记录不能证明右上角横幅出现，没找到也不能断言发送失败（记录可能已清除或尚未出现）。
3. **实际收到**：默认为“等待你确认”。只有用户点击“我收到了 / 没看到”才记录，后台回调不代替用户确认。

“发送一条测试通知”是手动动作，使用独立标识，不覆盖真实告警、不改变网络状态、不请求权限、不执行客户端或探测网络。超时不会自动重发。尚未提交的超时与提交前取消由同一状态锁仲裁；已提交但未确认显示“不确定”，不能冒充发送失败或已收到。旧测试回调不能覆盖新测试；同一测试的旧通知中心查询也不能覆盖新查询。

## 读取范围

通过本应用的 UNNotificationSettings 读取：授权、横幅/提醒开关、提醒样式、通知中心、声音、锁屏显示。授权变更在回到窗口及周期查询时刷新。

只匹配本应用测试通知的 identifier，不读取通知正文、其他应用通知、账号、聊天或凭据。测试结果和人工确认仅存在内存；重启后清空。复制报告不带测试关联序号、应用标识或本地路径。

专注模式、屏幕共享/镜像、锁屏期间的展示可能受系统控制。本工具不读取或修改这些状态，面板会说明需要在系统中核对。系统配置读取不到时明确显示“尚未确认”。

## 本轮实机证据

alpha.5 的真实仅观察模式读取到：已授权；本工具提醒启用；横幅、通知中心、声音、锁屏显示均开启；样式为横幅。
本轮只手动发送一条测试通知，系统接收回调成功，并在本应用通知中心列表中找到该唯一测试记录。人工收到状态保持“等待你确认”，未代用户点击任何确认按钮，未自动重发。

这仍不能确定用户先前没看到的原因，也不宣称横幅投递已由用户验收。未改系统通知设置、代理、时区或防火墙；未启动 Claude、未请求 Anthropic。

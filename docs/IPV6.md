# IPv6 检查与边界

IPv6 是正常网络能力。公网地址不等于泄漏；本工具没有验证官方客户端实际流量，也没有强制断网能力。

## 检查依据

macOS 适配器只读执行 `ifconfig` 和 `netstat -rn -f inet6`，连续采集两组本地证据，比较标准化结果。核心判断只消费接口状态、地址数量和外网路由所在接口，不依赖代理品牌或固定网卡名，不向界面、报告或事件输出原始 IPv6 地址、网关。

macOS 的合法零 flags 接口（例如 `stf0: flags=0<> mtu 1280`）按停用接口解析，不影响其他接口的检查。若无法取得有效证据，详情会区分接口/路由读取失败、接口/路由格式不兼容与两轮采样变化；这些状态仍阻止启动，且不会输出原始命令内容。

| 本地观察 | 结果与启动处理 |
| --- | --- |
| 已启用且活动（或活动状态不明）的接口上有可用公网范围地址 | 覆盖待确认，阻止新启动；没有默认路由也不直接放行 |
| 存在可用默认、分流默认、非本地网络或主机 IPv6 路由 | 覆盖待确认，阻止新启动；`utun` 不自动通过 |
| 接口已停用或明确断开，且没有外网路由证据 | 地址记入排除数量；仅作为本次未观察到公网路径的参考信息 |
| 地址为 tentative（非 optimistic）、duplicated、detached，且没有其他公网路径证据 | 暂不计为当前可用地址；仍监测后续变化 |
| 地址为 deprecated 或 optimistic | 仍可能发送数据，保持覆盖待确认 |
| 读取失败、空输出、格式不完整、接口与路由不一致或两组观察变化 | 无法确认，阻止新启动 |

路由检查包含默认、两个半默认、其他非本地前缀及主机路由；不把 reject/blackhole/未启用路由当成当前可用路径。本地链路、回环、组播与 ULA 专用路由不作为传统公网路由。ULA 配合 NAT64/NAT66、私有转发等仍不能由这些本地观察排除，故“未观察到公网路径”绝不代表全部 IPv6 流量受保护。默认和分流默认路由即使只有 ULA 源地址也会阻断。

## 代理覆盖与严格策略

当前版本不提供“IPv6 覆盖已验证”的认证路径。代理软件的 TUN/全局开关、接口名称和固定 Cloudflare HTTPS 请求成功，都不能单独证明 IPv6 覆盖，更不能证明所有客户端请求均遵循代理。界面明确分开展示“公网 IPv6 路径”和“代理覆盖”。

存在需要验证的公网路径或证据不完整时，没有忽略放行按钮。工具只提示检查代理 IPv6 支持；若用户确实不需要公网 IPv6，可自行评估将当前网络设为“仅本地链路”的影响。工具不修改系统设置；修改可能影响依赖公网 IPv6 的服务。当前版本不能仅靠勾选“代理支持 IPv6”解除阻断。

## 运行时与启动边界

IPv6 同时纳入每 5 秒的本地复核、完整检查最后复核和手动启动提交前复核。状态变化或读取失败会使旧启动许可失效，后台继续采样并去重通知。稳定恢复只恢复观察状态，仍需完整复检才能授予新启动许可。

这些复核不进行 IPv6 外联，不请求 Anthropic/Claude，不抓包、不终止进程、不阻断已运行客户端的网络。采样和最后一次读取与实际请求之间仍有空窗，不能当作 fail-closed 网络隔离。

## 模拟验证

- 跨平台纯规则测试：`cargo test -p guard-core --test ipv6_contract`。
- macOS 录制命令输出与解析测试：`cargo test -p guard-platform`。
- macOS 真实解析器和控制器组合的虚拟时间测试：`cargo test -p guard-service --test ipv6_runtime`。
- 前端提示、依据和建议展示：`npm test`（在 `apps/desktop`）。

测试仅使用文档地址、内存状态、录制输出和无副作用的启动计数器，不运行系统探测命令、真实客户端或外网请求。

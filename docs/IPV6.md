# IPv6 与代理预检边界

当前是 **代理预检模式**（`proxy_preflight`，策略版本 3），保留 IPv6。代理预检通过只说明已检查的指定代理链路符合当前要求，IPv4/IPv6 实际客户端流量覆盖始终未验证，不提供防直连或账号安全保证。

## 阻断和提醒

| 证据 | 状态 | 启动影响 |
| --- | --- | --- |
| 可用公网范围 IPv6 地址、默认/分流/其他候选路由 | 覆盖未验证（Warning） | 非阻断提醒，不要求关闭 IPv6 |
| IPv6 接口/路由读取、解析失败或两轮采样变化 | 观察不完整，覆盖未验证（Warning） | 非阻断提醒，绝不显示为覆盖通过 |
| 暂未观察到公网范围路径 | 本地观察信息（Info） | 不代表 IPv6 覆盖或未来网络已验证 |
| 系统代理、PAC/旁路、监听身份、HTTPS/TLS、出口或最终复核异常 | 阻断项未通过 | 拒绝启动 |
| 其他 Warning、任何 Fail/Skipped、缺项/重复项、配置无效、缺少基线或证据过期 | 阻断项未通过 | 拒绝启动 |

仅 `RuleId::Ipv6 + Status::Warning` 具有非阻断例外。后端统一计算并向界面提供 `blocksLaunch`，界面优先展示真正的阻断项。不能用导入报告、伪造非阻断字段、后台恢复或演示状态授权真实启动。没有手动意图、完整新鲜复检或最终提交前代理状态一致性，仍不能启动。

## 本地 IPv6 观察

完整检查只读执行 `ifconfig` 与 `netstat -rn -f inet6`，两组标准化观察需要一致；合法零 flags 停用接口（如 `stf0: flags=0<> mtu 1280`）不会被误判成格式错误。接口启停/连接状态、地址状态与路由均用于解释本次观察，不依赖代理品牌或固定网卡名，不向界面、事件或报告输出原始 IPv6 地址/网关。

停用、明确断开及暂不可用的地址分别计数；deprecated/optimistic 或状态未知的公网范围地址保留为候选。路由包括默认、半默认及其他非本地范围目标，不把 reject/blackhole/未启用路由当作当前可用候选。本地链路、回环范围、组播、ULA 专用范围不当成传统公网范围；ULA/NAT64/NAT66、私有转发等不能由这些观察排除。候选数量不代表实际向公网发送过请求，也不代表 TUN 已接管它们。

IPv6 快照只在完整检查时刷新。后台每 5 秒复核系统代理、监听身份、IPv4 默认路由，每 30 秒通过固定代理检查出口；已有路径/休眠事件仍使旧预检失效。后台不逐周期证明 IPv6 路由覆盖，不检测真实客户端直连包。

## 不需要关闭 IPv6

IPv6 是正常网络能力。用户可以保留它；不需要修改系统网络配置才能满足代理预检。TUN、全局模式、代理环境变量或 Cloudflare 成功均不能单独证明真实客户端所有请求都经代理。客户端是否实际遵循代理，与本机有无 IPv6 是不同问题。

工具没有 packet filter、kill switch、TLS 解密或强制进程隔离。代理异常会通知、拒绝新的启动；不会阻断、结束或重启已经运行的客户端。两次采样之间有空窗，不能宣传为强制防直连保护。

## IPv4 / IPv6 模拟验收

`proxy_transport_contract` 使用与真实启动相同的 `guard_core::proxy::ClientProxy` 环境配置，以真实 curl 为合作模拟客户端、假 HTTP CONNECT 代理和临时端口的 IPv4/IPv6 回环上游验证：

1. 正常请求经过代理，代理 CONNECT 和上游连接计数符合预期。
2. 代理端口不可用、拒绝 CONNECT、建立隧道前断开、建立隧道并收到请求后断开，均不回退直连。
3. 失败时上游计数为 0；随后显式直连回环上游成功，证明目标原本可达。

所有监听和转发地址限制为 `127.0.0.1` / `::1`；测试专用 `.invalid` 名称由 curl `--resolve` 映射到回环，避免 DNS/公网访问。配置和解析仅限测试进程，不修改系统代理、DNS、IPv6、VPN 或路由。监听线程、socket 和客户端均有超时与清理。

测试使用 HTTP + CONNECT，验证模拟传输路径，不是 TLS、真实 Claude、Electron/Node 全部网络栈或账号验收。生产 HTTPS 仍为固定 Cloudflare、严格证书验证、无任意 URL 覆写、无重定向和无直连回退；没有因模拟测试而放宽它。

```sh
cargo test -p guard-core --test ipv6_contract
cargo test -p guard-platform --test proxy_transport_contract
cargo test -p guard-service --test ipv6_runtime
```

上述测试不启动 Claude，不向 Anthropic/Claude 发送 HTTP、TLS 或 DNS 请求。CLI/Desktop 启动流程仅用无害计数器或静态脚本/config 断言验证，不能当作真实客户端已验收。
